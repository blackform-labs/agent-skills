# Agent Skills repository

## Delivery

- After completing and validating an authorized change in this repository, commit and push the task's files to the current tracking branch. Inspect the diff and stage only those files; preserve unrelated work. Stop and report if the branch, remote, or worktree makes that unsafe. Do not force-push.
- Do not create a release for every commit. Propose one when a new skill, a material workflow improvement, or a significant fix warrants a version. Routine documentation and minor corrections can accumulate.
- For a proposed release, inspect the changes since the previous release and prepare a version and concise, user-facing notes. Obtain explicit approval before creating or publishing the release unless the user has authorized that release. GitHub's published-release workflow sends the notes to Discord; do not send a separate message.
- Validate changed skills with the available skill validator, and run other checks proportionate to the change. Report what was actually verified.
